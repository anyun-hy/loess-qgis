# 当前实施状态

## v2.0 开发版本

当前源码的产品版本为 `2.0.0`，插件元数据与安装清单使用同一版本来源。
以下“已实现”指源码能力。当前源码仍是 v2.0 开发版本，macOS 与 Ubuntu 用户
default profile 的插件和推理项目已按同一源码清单同步；正式发布和双平台完整
真实模型验收仍未完成。

## v1.0 冻结回滚点

`v1.0` 固化 Ubuntu 升级 QGIS 4.2 之前的稳定状态：

| 平台 | QGIS 主机运行时 | 独立推理运行时 |
| --- | --- | --- |
| Ubuntu 24.04 | QGIS 3.44.x、Qt5、PyQt5 | Python 3.12、PyTorch 2.6.0 cu124、CUDA、RTX 3090 |
| macOS | QGIS 4.2.x、Qt6、PyQt6 | Python 3.12.13、PyTorch 2.7.1、MPS |

该标签只保留为迁移前的历史回滚边界，不得修改标签指向；当前分支已经
停止交付 QGIS 3/Qt5 运行时。

## 已实现

- macOS 与 Ubuntu QGIS 4.2/PyQt6/Qt6 共用一套源码，分别使用 MPS 与 CUDA；
- Ubuntu 插件拒绝非 Wayland QPA；日志筛选采用有界缓存和分帧重绘；
- QGIS GUI、runtime 调度/QProcess、PostgreSQL 监控和 pipeline 日志写入已分离到
  明确线程；高频日志按 100ms 批量传输、进度按 key 合并，Job 心跳按 5 秒集中
  更新，Artifact 清理的 SHA/删除不再占用 Qt 线程；
- runtime、监控和 SAM3 界面关闭采用非阻塞生命周期；输入冻结与 accepted 审计、
  已有 Run 加载、人工最终组装、拓扑检查和长期标签入库已任务化。取消与提交
  互斥，过期回调不能覆盖当前窗口，已有标签库使用同一数据库事务写入；
- 普通类别编辑按变化 FID 追踪，保存仅更新受影响类别的哈希；完整文件身份校验
  仍保留在恢复和最终组装边界，纯会话状态保存不重算类别文件；
- PostgreSQL-only Run 控制面，包含事务租约、恢复、失败包重置和 Artifact 引用；
- 恢复与重置前取得跨进程 Run 执行所有权；正式产物发布校验执行身份和 Job 租约，
  终态写入失败不得报告完成，最近任务索引保护完整的并发读改写；
- 原生 Qt 推理监控已分为总览、详细进度、结果与验收、事件与日志四页，采用
  可记忆的深蓝/浅色局部主题，并按实际 Run 显示 CUDA、MPS 或 CPU；停止仍在
  监控与主界面，恢复和重做失败包仍只在主界面；
- 新 Run 的开始、恢复、重做、Job 尝试、包内模型和十步组装阶段写入 PostgreSQL
  监控历史；历史尝试编号不复用重试预算，后续恢复保留旧失败并建立关联；
- 三个模型独立结果流与 approved Fusion 结果流；
- Work Package、Partition、V3 基线、V3.3 权威 Core 和四流并行组装；
- GeoParquet 中间数据、GeoPackage 最终数据和严格 coverage 验收；
- 公共分界拟合、人工分类工作区、SAM3 边界候选和 accepted labels；
- 源码中新 Run 默认限制最终公共边界双向偏移为 1 像元，超限减弱平滑或保留原始
  边界；在同一误差预算内合并冗余分段，保留净面积转移限制。已完成多类别隔离
  对照及回归检查，已部署两端，尚未完成整幅 Run 验收；
- 分辨率适配默认按 2m 参考参数换算，保留像元误差保护，同时限制实际距离。
  运行与组装共用换算并记录有效值；已验证五种分辨率的受控几何及冻结边界网格
  重放，已部署两端，尚未完成这些分辨率真实影像的分别推理验收；
- 主面板集中显示启动阻塞项，固定开始/停止入口；失败反馈说明影响、保留成果
  和对应任务入口。类别列表显示审核状态并共用一组操作，入库摘要显示目标、
  确认/拓扑状态、阻塞原因及本次实际新增数，推理完成不等同人工确认或入库；
- 可恢复的磁盘清理、最终制品大小观察报告和分阶段耗时。
- 几何 Job 使用 PSI/可用内存/Swap 驱动的动态并发与非阻塞降载；模型空间单元
  概率数组原位处理，并在矢量化前释放；

## 当前部署与验证范围

macOS 与 Ubuntu 用户 default profile 的插件和推理项目来自同一工作树快照，
包含最终折线偏移限制、顶点压缩和分辨率适配。清单、托管文件及权重校验通过，
既有输入、权重、项目身份、推理环境路径和成果保持不变；托管默认配置同步更新。

两端已安装的运行时通过分辨率换算、平滑误差、压缩和公共边界检查。主面板顺序、
模型版本、Fusion 对比、平滑参数、分辨率适配说明和键盘操作通过合成数据界面
检查：macOS 使用原生 QGIS Python 的离屏窗口，Ubuntu 使用原生 Wayland。
这些检查不等于真实影像整幅推理或用户完整操作验收。

此前版本隔离 QA 的真实 CUDA 小范围验证已从 Schema 2 Run 创建走到三个模型及 Fusion 四路最终矢量：
四个 `512×512` 切片、重叠 `192`，覆盖 `832×832` 源像素；8 个 Job 和四路结果
均为 ready，覆盖验收及输出哈希核验通过。验证使用独立 PostgreSQL 和输出目录，
未写入生产标签库。SAM3 仅验证真实 CUDA 加载，未验证交互修整。
原生 Wayland QGIS 已在隔离 profile 中加载已安装插件和四路真实矢量结果，并正常
退出；这不等于用户 default profile 中所有历史设置和完整操作流程都已验收。

该结果证明此范围内的功能链路可以执行，不证明整幅影像性能、长期稳定性、分类
准确率、人工修整与入库流程或 macOS 真实模型验收。

同一原始触发环境的修复版 GDB 对照和原版本无 GDB 对照均完成，未再次出现

停止后恢复、失败包重做、完整目标区域、长期运行稳定性、分类准确度、人工修整和

## 当前生产合同

- Fragmentation V3.3 是权威碎片治理方案，V3 是冻结基线和新 Run 的显式回滚项；
- `gap=0`、`overlap=0`、`outside=0` 是最终硬门；
- 模型、Fusion profile、输入和关键输出必须记录 SHA-256；
- 权重、输入、PostgreSQL 数据、QGIS 工程和 Run 输出不进入源码仓库；
- 历史文件状态库不恢复，必须用当前部署创建新 Run。
- 已有标签库事务需要 QGIS 宿主的 GDAL/OGR Python 绑定；缺少绑定时明确拒绝
  该次写入，不混入 Conda 推理环境，也不阻止插件其他功能加载。

## 自动验证

本地完整测试应在项目 `qgis` Conda 环境运行：

```bash
conda run -n qgis pytest -q
```

GitHub `quality` 只覆盖无 GPU/QGIS 依赖的源码、Shell、文档和静态合同。它不代表
CUDA、MPS、QGIS GUI 或真实模型资产已经验收。
