# 代码清理计划与保留边界

## 目标

减少无用途的控件、重复状态更新和生产目录中的职责混杂；不以删除行数为验收
指标，不改变已确认的四页设计、推理算法、恢复语义或用户数据。

## 分类与处理

| 类别 | 已确认对象 | 处理原则 |
| --- | --- | --- |
| 无显示用途的界面遗留 | 监控 `_bar`、`_summary`、`_stage_rail`、`_package_overview` | 删除控件和仅为它们服务的计算；必要的包 ID、耗时和原因保留在可见对象的详情中 |
| 隐藏控件充当数据存储 | Run、组装、覆盖验收摘要 | 改为普通字符串，由运行信息弹窗读取；不删除信息 |
| 隐藏控件充当格式化中间对象 | 边界处理 `_fit_label` | 阶段标签更新允许不提供标签，保留可见进度条、状态和工具提示 |
| 历史完成 Run 专用工具 | `fragmentation_postprocess.py` 及其 shell 入口 | 暂时保留；不是新 V5 Run 主链，但正式操作文档和分类工作区仍识别其产物 |
| 实验与评估工具 | `fragmentation_ab_experiment.py`、`subpixel_vectorize_experiment.py`、`evaluate_fragmentation_v33_replay.py` | 独立放在 `tools/experiments/`，保留 CLI 参数与输出合同，不进入生产部署 |
| 旧格式兼容 | 项目清单 Schema 1 迁移、旧模型事件解析 | 先确认仍需支持的项目/Run 范围，再决定停止支持；不能用本机一个新项目代表所有项目 |
| 当前生产依赖 | `fragmentation_v3.py`、`fragmentation_v33_candidate/` | 保留；前者仍是 V3.3 基线及显式回滚项，后者被正式运行引用，不能按名称删除 |
| 大型活跃模块 | 监控、分类修整、主面板、数据库层 | 按状态解释、查询、视图、事务职责逐批重构；不得通过搬移整类或新增兼容壳制造表面精简 |

## 实施顺序

### 第一批：不改变可见界面的遗留清理

1. 核对所有调用方、测试和弹窗消费者，确认控件没有可见入口。
2. 删除无用途控件、旧阶段导航 HTML、旧摘要遍历、隐藏进度条计算。
3. 将仍有用途的摘要从隐藏 QLabel 改为普通字符串；包 ID、Batch、降档原因和
   包耗时放在可见的包信息工具提示中，不因删控件丢失信息。
4. 保留现有四页布局、字体、主题、可见进度条、详情、日志和操作位置。
5. 用结构测试防止遗留控件回流，用原生 Qt 测试验证弹窗内容和启动/运行/终态。

### 第二批：工具与兼容边界整理

先列出实验工具的导入、命令、相对资源路径和文档引用，再确定独立工具目录及
部署清单。移动前必须验证 CLI、源码指纹和两平台安装测试。历史处理工具的移除
还需用户确认不再支持相应历史操作；不能仅凭新流程不调用就删除。

工具迁移的已知约束：

| 工具 | 迁移前必须处理的依赖 | 验证重点 |
| --- | --- | --- |
| `fragmentation_ab_experiment.py` | 从生产模块导入 `deployment_config`、`small_component_regularizer` | 独立 CLI 导入、参数、样本选择及输出目录边界；不能复制一份生产算法到工具目录 |
| `subpixel_vectorize_experiment.py` | `rasterio_compat`、基础及参考评估使用的 `boundary_ab_validate`、测试导入 | 迁移后导入、CLI、小型概率样本输出和既有算法测试 |
| `evaluate_fragmentation_v33_replay.py` | 通过 `__file__` 的父目录寻找 `qgis_plugins` 或部署 `runtime` | 源码运行与部署项目输入的路径解析、历史哈希校验和 CLI |
| `fragmentation_postprocess.py` | shell 入口、正式操作文档、分类工作区的产物元数据读取 | 即使以后停止提供执行工具，也不能直接删除读取既有成果所需的代码 |

实验工具统一放在仓库 `tools/experiments/`，默认不进入生产部署；新命令与部署
范围见 [实验工具](../operations/EXPERIMENT_TOOLS.md)，源码清单与安装脚本测试
必须覆盖这一边界。
不保留只为旧路径跳转的重复实现，不删除实验输入或结果，不把迁移行数算作死
代码删除收益。

### 第三批：大型模块职责拆分

根据具体调用图选择一个独立职责作为一批，优先纯数据解释与格式化；保留事务
所有权、线程归属、状态代次和生命周期。每批提交前先通过相关行为测试，再跑
完整回归。数据库与调度器的大规模重构需要单独提出具体设计和风险供审核。

监控先拆出 `core/monitor_progress.py`：仅负责步骤归属、等待计数、辅助任务组
完成度和阶段文案，不导入 Qt、不查询数据库、不保存运行状态。窗口消费其计算
结果，仍自行处理刷新、控制过程和终态。总体比例不是组装阶段完成的证据，也
不代表剩余时间；该模块不加入推理进程的共享运行时清单。

日志解释与磁盘分页归入 `core/monitor_logs.py`，统一供实时日志呈现和历史查询
使用。解析函数不保存状态，分页读取仍仅由现有查询 worker 调用，保留字节预算、
游标和异常合同。该模块不导入 Qt、不新增轮询、不写日志或任务状态；历史错误
仍只证明事件发生，不能凭一条日志推断当前已恢复。只为旧测试服务的日志兼容
函数删除，测试直接调用正式解析接口，不保留包装层。

### 收束批次：有调用证据的剩余遗留

本次源码清理以以下清单作为终点，不要求把每个大型文件拆成小文件：

| 对象 | 处理与验收边界 |
| --- | --- |
| 监控旧 `STATUS_COLORS`、`STREAM_TABLE_VISIBLE_ROWS` 及无引用导入 | 删除；颜色仍来自主题函数，表格仍由 `fit_rows_to_content(max_rows=5)` 控制。测试核对实际配置与原生表格尺寸，不再验证无用途常量存在 |
| 分类修整单对象候选显示路径 | 删除没有调用入口的 `_show_manual_candidate`、对应单对象成员及清理方法；保留批量候选和参考高亮。用原生 QGIS 临时几何验证多候选显示、刷新和场景清理 |
| 旧 `_accepted_layer_for_check` | 删除无调用的私有读取方法；保留 `RefinementTask` 后台拓扑检查与 accepted 入库，相关行为与门禁测试必须继续通过 |
| 主面板、分类修整活跃职责 | 本次不再拆分；已确认存在信号、调用或数据生命周期依赖，不能按行数或方法名删除 |
| 数据库、调度与恢复 | 不实施结构改造；先有具体故障或测量证据，再单独提出变更范围与风险 |

完成以上清单、回归和原生验证后，这轮有明确对象的源码清理收束。历史兼容保留
是明确边界，不是无限待清理项。真实 CUDA/MPS/Wayland 大任务性能测量、历史
写入开销测量及发布验收另行开展，不用源码拆分或测试数量代替。若核对时发现
新风险，记录具体证据并提出下一项建议，不自动扩充本轮实施范围。

## 补充清理：已脱离当前调用链的接口

仓库级复核后，补充清理限于下列已核对的对象；不重新开启大型模块拆分，也不
把仍可独立执行的命令行工具当作无用代码。

| 对象 | 清理与保留边界 |
| --- | --- |
| 旧 Tile 预切类、隐藏 Tile 表和逐 Tile 监听 | 删除孤立链及其计时缓存；存储预检、后台输入准备和按工作包物化保留。准备阶段停止须清理本次上下文，延迟回调不得重启已停止流程 |
| 旧差分与独立图层辅助方法 | 删除无调用的方法与专用导入；保留当前结果流、分类工作区、Accepted 跳过、正式成果和拓扑图层加载 |
| 数据库孤立接口 | 删除无调用的状态写入、分步产物关联与对象查询接口，以及旧 V3.3 分步发布 helper；不改表结构、现行原子发布事务、lease 校验、引用计数或恢复语义 |
| 旧流程 HTML 与无调用计算 helper | 移除指向已删除自动入口的 `INFERENCE_MECHANISM.html` 和孤立 helper；当前调用关系以 `PRODUCTION_CALL_GRAPH.md` 为准 |
| 仍有用途的兼容与工具 | 保留 SAM 独立 CLI 及交互预测、历史 Run 修复工具、Schema 1 读取与迁移、崩溃窗口恢复、V3 基线与 V3.3 生产依赖 |

按风险依次处理启停生命周期、普通辅助方法和数据库接口，每批先审核调用证据
与相关测试。数据库清理只删不可达接口，不用此授权进行事务重构或生产迁移。

## 验收与停止条件

- 第一批删除的属性和方法在当前源码及运行路径中不再存在，不保留空实现或别名。
- 运行信息仍包含 Run、设备、创建年龄、监控时长、组装和验收摘要；无 Run 时
  显示准备/未知，不编造成功。
- 正式 Run 进度仍来自数据库任务组；准备进度不能覆盖停止或终态。
- 四页、筛选分页、Warning/Error 历史、停止/恢复/重做位置及关闭窗口行为不变。
- 在 Conda `qgis` 跑相关和完整测试；原生 Qt 用独立 QGIS Python 验证，不把离屏
  结果当成 Ubuntu Wayland 或真实 CUDA/MPS Run 验收。
- 遇到外部使用范围不明、有效恢复依赖或缺少行为验证时，保留该项并列明原因；
  不为了清理继续扩大删除范围。
- 各批次须满足上述前提；Git 提交、推送、部署、环境变更和
  用户数据删除分别需要授权，不随代码整理自动执行。
