# 项目思想：为什么建设这套标注工作台

> **文档职责：WHY。** 本文只说明项目要解决的问题、价值、原则和范围，不
> 定义实现细节，也不作为验收依据。当前设计合同见
> [`ARCHITECTURE.md`](ARCHITECTURE.md)，真实状态见
> [`CURRENT_STATUS.md`](CURRENT_STATUS.md)。

## 要解决的问题

大幅遥感影像的土地利用矢量标注同时面临三类成本：人工逐面绘制效率低，单一语义模型在不同类别上的表现不稳定，自动结果又必须经过可追溯的人工作业才能进入长期标签库。

项目因此不是要用一个模型替代标注人员，而是要在 QGIS 中建立一个可比较、可修整、可确认的半自动标注工作台：让多个正式部署模型提供独立候选，让融合结果提供另一种候选，让 SAM3 专注于边界修整，最后由用户按类别选择来源、编辑并确认。

## 期望产生的价值

- 降低大范围初始矢量绘制的重复劳动，把人工精力集中在比较、修边和质量控制上。
- 保留每个模型、融合结果和 SAM3 修整结果的来源，使错误能够定位、结果能够复核。
- 不强迫一个模型在所有类别上充当唯一裁判，允许按类别选择更合适的候选来源。
- 将训练工程与插件运行时解耦：训练侧交付稳定部署资产，插件只按固定契约消费资产。
- 让一次运行可以停止、恢复、重试和长期留存，避免旧结果被新运行静默覆盖。
- 保护已经确认的标签，形成可持续积累的长期标签数据闭环。

## 核心原则

1. **类别判断与边界修整应保持职责分离。** 这样可以避免修边工具改变语义结论。
2. **多个模型应作为可比较、可追溯的候选来源。** 这样用户可以按类别判断哪个来源更可信；具体保存规则由主文档定义。
3. **融合结果应保持独立来源身份。** 它提供另一种候选，而不是掩盖各模型差异；具体融合方法由主文档定义。
4. **大图分块不应人为制造地物边界。** 切片只是处理大图的手段，不能降低最终矢量结果的连续性。
5. **人工确认是正式入库前的必要环节。** 自动结果不能绕过审核直接进入长期标签库。
6. **过程必须可追溯。** 用户应能回查结果来源、配置、版本和运行状态；具体字段与记录格式由主文档定义。
7. **正式完成以真实部署资产和真实运行证据为准。** 测试资产只能证明被测试的软件能力，不能代替正式模型验收。

## 范围边界

本仓库负责 QGIS 插件、部署推理运行时、结果组织、分类修整、拓扑检查和标签入库闭环。正式模型的训练、checkpoint 选择和 TorchScript 导出属于外部训练任务；本仓库只接收并验证其部署资产。

因此：

- 本文不规定字段、模块、算法、状态机、文件树、资产清单或测试步骤；这些
  内容由 `ARCHITECTURE.md` 和实际代码合同定义。
- 本文不记录“已经完成什么”；真实进度、证据和阻塞状态只写入
  [`CURRENT_STATUS.md`](CURRENT_STATUS.md)。

## 项目成功的含义

最终成功不是“模型能输出一张 mask”，而是用户能在 QGIS 中稳定完成以下工作：比较不同语义来源，按类别修整和编辑，检查拓扑，确认来源，并把可追溯的最终结果安全写入长期标签库。

具体完成条件以 `ARCHITECTURE.md`、`CURRENT_STATUS.md` 和对应自动/实机验收
合同为准。
